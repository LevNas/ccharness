# arc-handoff — セッション内のアークの切り替え

1 つのセッションを長く使うとき、作業のまとまり（アーク）の境目で実行します。compaction のあとに残るのはファイルに書いたものだけです。そこで、会話にある状態をファイルへ移してから `/compact` します。`/compact` は利用者が実行するコマンドなので、このスキルは実行せず、打つ一行を示します。

## 手順（順に実施）

1. **区切りを確かめる**: いまのアークの完了条件（テスト・ビルド・レビュー）を満たしたか、満たさずに中断するのかを一行で書きます。
2. **状態を書き出す**:
   - 進捗: タスクファイル（`.claude/tasks/` など）か issue のコメントに、終わったこと・残り・次の一手を書きます。
   - 決定: 会話の中で利用者が決め、まだファイルに無いことを書きます。判断の記録はナレッジベースへ（ccmemo があれば `/record-knowledge`）。
   - 変更: 未コミットの変更があればコミットします。push は指示があるときだけです。
3. **`/compact` の一行を示す**: 次のアークの焦点を 1〜2 文で書きます。
   例: `/compact 次は <次の issue> の実装。<いまの issue> は <PR> でマージ済み、残りは issue に記載。`
4. **次のアークの入口を示す**: 最初に読むファイルや issue と、最初の一手を書きます。

## 使い分け

- 関係の無い作業へ移るとき: `/compact` ではなく、`/rename` してから `/clear` を勧めます。
- セッションを終えるとき: session-wrap を使います。
- 書き出す先（issue もタスクファイルも）が無いときは、作るかどうかを利用者に確認します。

## 背景

- CLAUDE.md と `paths:` の無い rules は compaction のあとに読み直されます。skill は直近に使ったものの先頭 5,000 トークンだけが戻ります。会話の中だけの指示は消えます。
- CLAUDE.md の `Compact Instructions` 節は、要約に残す項目を指定します。このスキルは、その要約に頼らずに済むよう、先にファイルへ書き出す手順です。
