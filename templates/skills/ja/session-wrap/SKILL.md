# session-wrap — セッション終了時の定例

## トリガー

セッション終了の合図（「終わります」「お疲れさま」など）があれば、明示指示がなくても本手順を実施してからコミットします。作業の明確な区切りでも実行してかまいません。マージ時レビューが pass または fail を返したときも実行します。

## マージ時レビューが fail のとき

session-wrap は実行します。判定、ブロッカーになった指摘の要約、次の一手、修正ラウンドの回数を記録します。記録先はタスク・進捗ファイルと issue コメントで、ナレッジにするのは教訓があるときだけです。これらの記録は、フィーチャーブランチではなく、**別のブランチを切ってデフォルトブランチへの PR** に載せます。フィーチャーブランチは破棄されることがあるためです。

## 終了条件

session-wrap 自身のブランチや PR は、レビューの結果にかかわらず、再び session-wrap の対象にしません。そのレビューが fail したら、その PR の中で直します。

## 手順（順に実施）

1. **進捗更新**: 進行中のプランやタスクの状態を更新します（`.claude/tasks/` やプロジェクトの進捗ファイル）。
2. **issue 更新**: 関連する issue にコメント、ラベル付与、クローズを行います。該当 issue が無ければスキップ可。必要なら新規起票を提案します。
3. **ナレッジ記録**: 設計判断・落とし穴・課題解決・指摘された誤りを記録します（ccmemo が入っていれば `/record-knowledge`）。
4. **繰り返した失敗の出口**: このセッションで ccevolve（入っていれば）が「同じ失敗が N 回目」と知らせた件があれば、その件だけを `/promote-to-computation` に渡し、計算（hook・lint・テスト・許可の規則）にする案を出してもらいます。案を採るかどうかは利用者が決めるので、ここでは適用しません。知らせが無ければ呼びません。知らせは会話の中にしか無いので、compaction より前の件は拾えません。
5. **コミット**: 変更をコミットします。push は明示指示がない限り行いません。コミットメッセージの言語はリポジトリの規約に従います。

## スキップ規則

- 該当のないステップはスキップできます。
- ただしスキップした旨を必ず報告します。
